# LIM Web

LIM 的标准 Web 聊天客户端。界面沿用潮汐主题：深色为「涨潮」，浅色为「退潮」，左侧导轨带有缓慢漂移的波浪动效。账号版支持注册、登录、刷新恢复、浏览器自动登记设备、按用户名找人、发起私聊/小群、管理设备，以及宿主可读文字消息的收发、历史补齐与离线缓存。界面明确标明「宿主可读」；MLS 端到端加密尚未实现。

## 启动双端 demo

在仓库根目录执行以下命令。`xmake dev` 会自动定位当前构建配置下的 `lim-server` 产物并按需构建；`--web-port` 可换端口，`--install` 可在缺少依赖时自动安装。

```sh
pnpm --dir web install --frozen-lockfile   # 首次
xmake dev
```

等价的手工步骤（其他平台需传入实际的 `lim-server` 可执行文件路径，启动脚本使用 Python 3.11+）：

```sh
xmake build lim-server
python3 web/demo.py build/xmake/macosx/arm64/debug/lim-server
```

打开 [本地客户端](http://127.0.0.1:5173/)。脚本会临时启动 SQLite 服务，注册 `alice` 和 `bob` 两个账号、自动登记演示设备、创建一段私聊并写入两条示例消息。终端会打印两个账号的用户名和统一密码。

请使用**两个独立浏览器上下文**（例如两个浏览器配置文件，或一个普通窗口加一个隐私窗口）分别登录 Alice 和 Bob：同源普通标签页会共享 `localStorage` 中的刷新令牌，后登录的账号会恢复前一个账号。登录后新浏览器设备会继承账号已有会话目录；这正是账号级成员与设备授权分离的效果。`Ctrl+C` 停止服务并清理临时数据库。

已有 `lim-server` 时，也可以用两个 xmake 任务分别启动持久后端与前端：`xmake dev-server` 使用 `build/dev/` 下的持久 SQLite 数据库，`xmake dev-web` 默认代理到 `http://127.0.0.1:7400`，可用 `--backend-url` 指向其他后端。普通用户直接注册或登录；折叠的「设备令牌」页签仍可连接旧版受控设备。浏览器前进后退可用：会话地址是 `/c/{conversation_id}`。

```sh
xmake dev-server   # 终端 1
xmake dev-web      # 终端 2

# 或手工设置转发目标
LIM_SERVER_URL=http://127.0.0.1:7400 pnpm dev
```

## 产品流程

1. 输入用户名、密码和昵称注册；浏览器生成稳定的 `device_id`，并以可读名称自动登记为当前账号的设备。
2. 刷新页面后从本地认证记录恢复身份；在线时用刷新令牌轮换访问令牌，多标签页通过 Web Locks 串行续期。
3. 右上角「发起聊天」按用户名前缀搜索账号。选择一个目标创建去重私聊，选择多个目标并填写名称创建小群。
4. 会话目录按账号授权，同一账号的新设备登录后自动看到已有会话；事件携带可信 `account_id`、用户名和昵称，因此同账号另一台设备发出的消息仍显示为「我的消息」。
5. 账号菜单可查看设备、撤销其他设备或当前设备、退出登录，以及退出并清除本机消息缓存。撤销设备会吊销该设备的登录会话；退出登录只结束当前访问会话。
6. 当前所有会话仍是 `host` 模式，正文由服务端保存和投递。登录成功不等于能够解密端到端加密历史；MLS 仍是后续阶段。

## 技术选型

| 层 | 选择与职责 |
| --- | --- |
| 基础 | React 19、TypeScript 6（`strict`）、Vite 8；沿用现有脚手架。开发与 CI 使用 Node.js 26 LTS 和 pnpm 11，以 `pnpm-lock.yaml` 锁定依赖。 |
| 路由与布局 | React Router 声明式路由，支持会话链接和浏览器前进后退。桌面并列展示导轨、会话目录、消息区与可选的信息面板，窄屏在目录与消息之间切换。 |
| 消息列表 | React Virtuoso（MIT 许可的 `react-virtuoso`）渲染可变高度的消息列表。向上加载历史时保持阅读位置，位于底部时跟随新消息。 |
| 基础组件 | shadcn/ui 的 Radix 版本提供按钮、输入框、菜单、弹层与对话框，源码按需引入；账号和设备面板使用项目内组合组件。 |
| 样式 | Tailwind CSS 4 通过 `@tailwindcss/vite` 接入，用于布局与响应式规则；`index.css` 定义潮汐色板，CSS Modules 承载消息、输入器和侧栏的局部样式。 |
| 协议 | 原生 `fetch` 与 `AbortController`，使用 Zod 4 校验 RPC 响应。TypeScript 协议模块独立于 React，统一解析错误、UUID 和十进制字符串序号；访问令牌过期时自动续期并重放一次请求。 |
| 数据 | IndexedDB + Dexie 存储消息、同步游标、会话目录和待发队列；通过 `dexie-react-hooks` 订阅本地查询。`chat/store.tsx` 把会话目录、时间线、全局投递和同步状态收敛为一个上下文。 |
| 验证 | `pnpm lint` 检查代码，`pnpm build` 检查 TypeScript 并打包；CI 新增 Web lint/build 门禁。浏览器联调使用两个隔离上下文和真实 `lim-server`。 |

## 源码结构

| 路径 | 职责 |
| --- | --- |
| `src/App.tsx` | 账号登录/注册入口、登录恢复、退出流程、账号与设备面板、工作区外壳。 |
| `src/chat/auth.ts` | 本地认证记录、稳定设备 ID、可读设备名与多标签页刷新轮换。 |
| `src/chat/protocol.ts` | JSON-RPC、公开账号方法、动态令牌自动续期、长轮询与错误语义，不含 React。 |
| `src/chat/sync.ts` | 历史补齐、长轮询循环与单条待发消息投递。 |
| `src/chat/storage.ts` | Dexie v2 表结构、目录缓存、游标推进、消息账号归属和待发队列。 |
| `src/chat/store.tsx` | `ChatProvider`：目录、本地时间线、跨会话待发泵与操作收敛。 |
| `src/components/*` | 导轨、会话目录、会话头部、消息气泡、输入器、信息面板与波浪装饰。 |
| `src/theme.ts`、`src/ThemeProvider.tsx` | 退潮／涨潮外观切换，按设备记忆选择。 |

## 同步与部署

- 首版用 `POST /rpc` 完成认证、目录、发送和事件补齐，活动会话通过 `/v1/conversations/{id}/wait` 等待新消息。前台每 30 秒刷新目录，重连及页面重新可见时立即对账。收到提示时按已保存的游标拉取，切换会话或退出时取消旧等待。WebSocket 尚未实现。[JSON-RPC](../docs/rpc.md) · [长轮询契约](../docs/protocol.md#http-长轮询)
- 目录、消息和待发队列按设备与恢复代次隔离并持久化。网络断开时先展示缓存目录和历史，输入器继续可写；消息进入全局待发队列，联网且目录可用后自动按会话串行投递，不依赖当前打开的页面。失败项可重试和复制正文。
- 发送前先保存原始正文、内容类型和 `client_message_id`。超时后按原键和原文重试，恢复代次变化时停止旧请求自动重发。缓存按设备与恢复代次隔离；认证记录保存在 `localStorage`，生产环境应进一步迁移到 `HttpOnly` Cookie 与同源 BFF。TLS 反向代理应同源提供静态文件，并转发 `/rpc` 和 `/v1/` 到回环上的 `lim-server`。
- 退出登录会吊销当前访问会话；「退出并清除本机缓存」另清空 IndexedDB 中的目录、消息、游标和待发记录。撤销设备不等于清除该设备已经下载到本地的旧明文，因此设备丢失时应同时清理浏览器数据。
- MLS 接入以项目共用的密码库选型和浏览器环境验证为前置条件。浏览器端将按协议原子保存 MLS 状态、事件处理进度和待发密文。[加密与信任设计](../docs/security.md#多设备-历史与状态持久化)

## 客户端行为

- 会话列表显示真实昵称/群名、完整编号和最新序号；搜索框支持按名称或编号过滤，`⌘K`（Windows 为 `Ctrl+K`）聚焦搜索框。
- 消息区按可信发送账号分组显示。自己的消息贴右侧、使用潮水绿气泡；其他账号贴左侧并显示昵称/用户名。气泡下方显示服务端序号或待发状态，悬停消息可复制正文。
- 首次打开会话加载最近 48 条可见消息，列表顶部的波浪分隔提示「这里是潮水的起点」或可继续打捞更早消息。离线时仍显示已缓存消息并标注状态。
- 右上角信息面板显示会话可见起点、最新序号、恢复代次、当前账号与设备，以及本地同步游标，并可触发加载更早消息、刷新目录或重新同步。
- 导轨可在涨潮（深色）与退潮（浅色）之间切换，选择写入 `localStorage`；账号菜单提供设备管理和退出登录。
- 浏览器中的宿主可读消息、待发内容和草稿保存在本机。关闭标签页不会清除缓存；需要移除本机副本时使用账号与设备面板中的清除入口。
