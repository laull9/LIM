# 实施与验收

## 实际进度与下一切片

当前可构建的是模块接口与外框解析器。SQLite 文件在设计探针中验证了写入串行化、顺序、幂等键唯一性、回滚和读快照。HTTP 监听、鉴权、存储适配器、MLS 客户端和资源基准仍待实现。

| 顺序 | 可使用的交付 | 验收 |
| --- | --- | --- |
| 1 嵌入式收发 | SQLite 适配器、迁移、宿主身份映射、管理建群与成员操作。首个消费者是本地 Agent Harness | 两主体发送、重开文件补齐；同键同字节返回同回执，异文拒绝；撤销与发送竞争、重新加入下界、过期墓碑 |
| 2 独立守护进程 | `lim-server` 薄入口、配置/凭据管理、HTTP 发送/补齐、WS 提示、TLS 部署样例 | 临时数据目录冷启动；两个真实客户端收发；丢 ACK、丢提示、连接慢读、磁盘满和关闭时在途请求 |
| 3 默认加密 IM | MLS 库选型及标准向量、设备授权、单聊、小群 Commit/Welcome、客户端状态持久化 | 两客户端真实加解密；撤销冻结、并发 Commit、离线新成员、恶意密文、恢复代次切换。未支持 MLS 的预览构建拒绝默认加密建群 |
| 4 发布 | 备份/恢复、观测、Linux 打包、资源压测、安全审查 | 干净机器独立部署与嵌入消费者构建，恢复演练，公布原始性能结果与工具链版本 |

host 模式允许团队先验证可读的 Agent 工作流。默认加密 IM 的发布门槛保留真实客户端联调。PostgreSQL 适配器、多实例路由、联邦、音视频和模型执行器均不进入首版依赖。

## 性能预算与测量方法

下表是设计目标，尚无服务器压测数据。首个基准使用 Linux x86-64、2 vCPU、512 MiB cgroup、本地 SSD、Release 构建。压测端独立，固定 1 KiB 消息、每秒 20 次提交、80% 单聊与 20% 八人会话，所有收件人均通过真实网络协议补齐。启用 SQLite WAL/FULL，记录文件系统、SQLite 版本与 checkpoint 频率。

| 指标 | 目标与口径 |
| --- | --- |
| 空载 RSS | 数据库打开、监听就绪并空闲 60 秒后 ≤ 16 MiB，独立记录 TLS 代理占用 |
| 256 在线连接稳态 | 守护进程 RSS ≤ 32 MiB。用 /proc/PID/smaps_rollup 采样 RSS/PSS，另报峰值和 cgroup memory.current |
| 服务端提交 P99 | ≤ 20 ms，从完整请求到达至 durable ACK 可发送，含调度与队列等待 |
| MLS 在线端到端 P99 | ≤ 150 ms，双端到服务器各 20 ms RTT，同一压测进程单调计时，覆盖加密、提示、拉取、验证及本地保存 |

预热 2 分钟、测 15 分钟、重复三轮。分别测 0/64/256 连接与固定速率发包；记录成功/失败/超时、P50/P95/P99、CPU、WAL 大小、页缓存、队列高水位和慢连接数。增加一个不读 socket 的客户端，再增加到达配额上限的突发流量，检查健康请求的延迟与内存曲线。验证故障时不把被拒请求记作成功。用对照实验证明是否需要组提交或增加读连接。

## 恢复与兼容

在提交前、提交后 ACK 前、提示前后分别终止进程，重启核对同一个逻辑事件。备份回退测试要求轮换代次、清退凭据和复核当时的成员与撤销状态。旧 MLS 组先冻结，待身份复核和新 Welcome 完成后恢复。日志超期、目录超期和 Agent 工具副作用分别验证。macOS、Windows、ARM64、TLS 库及实际 MLS 实现由对应阶段单独建立验证矩阵。
