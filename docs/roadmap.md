# LIM 实施与验收路线

## 仓库起点

目前仓库包含 C++23 `src/main.cppm` 启动示例、内置 ltool、xmake 模板和一个 Catch2 算术测试。本轮完成 README 与顶层设计文档。以下所有里程碑均待实施。

已有 `xmake.lua` 使用 `my_app` 目标、全局关闭告警、未锁定 Catch2、通配源码和未区分配置的产物路径；根目录尚无 CMake 入口。现有改动予以保留，M0 集中完成工程基线调整。

## 实施顺序

| 阶段 | 可交付成果 | 验收条件 |
| --- | --- | --- |
| M0 工程与技术验证 | CMake/xmake、工具链与依赖锁定、LWeb/WS/libpq 探针、MLS 库选型 | 两入口独立干净构建并运行相同行为测试；真实 WS 并发写入和关闭；数据库提交与回滚；MLS 向量与互操作报告 |
| M1 身份与协议 | v1 schema、账号与设备授权、MLS 参考客户端、初始建群 | 首次信任与核验状态可区分；错误身份、坏证书和重复包被拒绝；两客户端真实加密往返 |
| M2 可靠单聊热路径 | 会话日志、幂等、直推、outbox、断线补齐 | ACK 丢失重试只有一个逻辑事件；进程在提交前后被杀均可恢复；完成首份 E2EE 延迟报告 |
| M3 群聊与多设备 | roster、Commit/epoch、Welcome、角色、撤销冻结 | 并发 Commit 唯一胜者；移除后新消息隔离；新设备历史策略；客户端 MLS 状态崩溃恢复 |
| M4 容量与低延迟 | 有界队列、隔离线程池、限流、指标、压测工具 | 达到基准延迟目标；慢连接、热群和登录洪峰不拖垮健康会话；稳定负载资源曲线可解释 |
| M5 自托管发布 | 配置模板、Linux 包/容器、迁移、备份、恢复与运维文档 | 干净环境部署；真实 TLS/E2EE 联调；故障恢复演练；密码库及集成安全审查闭环 |

每阶段以可运行的完整业务路径交付。首个端到端里程碑就是密文单聊，后续群聊复用相同事件、事务与加密契约。

## 工程基线

M0 保留 C++23 方向，分别探测 `import std`、named modules、协程和结果类型，记录编译器与标准库的精确组合。Linux 生产与 macOS 开发矩阵各自验证；Windows 进入后续独立适配阶段。

- 主文档入口设为 CMake，共享 presets 管理 Debug/Release/ASan+UBSan；xmake 保持等价源码、宏、依赖和测试，并启用依赖锁文件。
- 两套构建使用显式源码清单。产物按构建系统、平台、架构和配置隔离；同时隔离 xmake 配置缓存，避免不同配置互相覆盖。
- 本项目目标启用规范告警、禁用非标准扩展，保留异常与 RTTI；第三方依赖单独管理告警。
- 固定 clang-format 主版本和项目配置；测试复用 Catch2，逐步加入真实行为用例。
- PostgreSQL/libpq 18 为首版设计基线；引入时锁定具体安全补丁版本。TLS 入口、libsodium、MLS 实现和现有 ltool 快照建立版本、许可与升级记录。
- LWeb 适配器验证真实 socket、消息大小限制、串行写、取消和退出。标准库 modules 与三方头文件互操作在两入口执行最小探针。

完成 M0 后，将经过运行的最低版本与完整构建命令写回 README。无需在设计阶段创建空业务目录或伪实现。

## 延迟验收

“无延迟”的工程目标是在线沟通无明显等待。使用真实 MLS 加密客户端、持久化数据库与 TLS 测量，计入客户端加解密和状态持久化。

| 指标 | 起止点 | 首轮目标 |
| --- | --- | --- |
| 服务端处理 | 完整有效消息到达 → 事务提交完成并将事件交给投递组件 | P95 ≤ 10 ms，P99 ≤ 20 ms |
| 在线端到端 | 发送客户端提交用户动作、尚未加密 → 接收客户端验证、解密并持久化完成 | P95 ≤ 50 ms，P99 ≤ 100 ms |
| 持久化确认 | 发送用户动作 → 发送端持久化 `accepted` 状态 | P99 ≤ 100 ms |

这些数值是验收目标，当前尚无实测结果。首轮基准环境固定如下，任何调整需同时记录新基线：

- Release 构建；应用主机 4 vCPU / 8 GiB，数据库主机 4 vCPU / 8 GiB 和本地 NVMe，二者 RTT ≤ 1 ms；压测客户端使用独立主机，至少 8 vCPU / 16 GiB。
- 1,000 条已认证在线设备连接，200 条业务提交/秒；80% 单聊、20% 16 设备群聊，正文 1 KiB；接收端全部在线并持续读取。
- 同一发送动作按所有应收设备分别记录投递延迟，并另报最慢收件人延迟；吞吐同时报告逻辑提交数与实际投递份数。
- 客户端到服务端 RTT 各 20 ms，无主动注入丢包。另跑 80 ms RTT、1% 丢包、移动网络重连与 128 人群的扩展场景，单独报告结果。
- 保持 TLS、MLS、身份检查、WAL 持久化和后台清理开启。稳态测量前预热 2 分钟，持续 15 分钟，至少重复三轮；首条消息、建群和换钥分别测量。

发送和接收测试客户端由同一压测进程使用统一单调时钟计时，服务器使用自己的单调时钟测量内部阶段，避免跨主机直接相减时间戳。真实客户端 UI 渲染延迟在客户端集成阶段另测，服务端基准覆盖到接收端可安全展示消息的时刻。

采用按计划发起的负载并记录排队等待，避免只在上一条请求完成后才发下一条造成采样偏差。报告 P50/P95/P99/最大值、失败率、重试率、丢失与重复数、CPU、RSS、磁盘延迟、网络流量、锁等待和 outbox 年龄。失败与超时保留在统计中，并提供原始数据、命令和工具版本。

低延迟优化顺序：定位等待阶段 → 缩短锁与事务 → 减少拷贝和编码 → 调整线程池与连接数 → 按测量结果选择批量或异步数据库驱动。所有优化同时通过加密与可靠性回归。

## 必须覆盖的行为与故障

| 领域 | 验收用例 |
| --- | --- |
| 消息幂等 | 并发重复发送；同键不同密文；ACK 丢失；原请求成功后 epoch 改变；幂等记录进入过期状态 |
| 事务恢复 | 事件写入前、提交前、提交后、直推后、outbox 标记前分别终止进程；恢复后查询唯一事实 |
| 顺序与同步 | 同会话并发发送；实时推送与分页补齐交错；Commit 缺口；目录事件丢提示；保留期过期 |
| 成员权限 | 非成员发送和读取；管理员越权；单聊并发创建；群角色转让；退群后重新加入 |
| 设备撤销 | 发送与撤销竞争；撤销与新群关联竞争；所有相关群冻结；无在线设备时等待换钥 |
| 密码学集成 | 官方向量与跨实现互通；坏签名、坏标签、跨群重放；身份替换；KeyPackage 重用；新旧 epoch 隔离 |
| 客户端状态 | 加密后发送前崩溃；解密后游标前崩溃；本地存储写失败；待提交 Commit 失败后重新同步 |
| 资源与取消 | 慢连接与热群；全局队列满；数据库超时；密码验证洪峰；关闭过程有在途事务 |
| 恢复部署 | 数据库重启；磁盘满；备份回退后的恢复代次与群重建；schema 不兼容；TLS 过期或配置缺失 |

网络测试使用本地 socket 和可控故障注入；集成测试使用独立 PostgreSQL 数据库，隔离端口、schema 和临时文件。跨模块生命周期修改运行 ASan+UBSan，并发实现使用独立 TSan 配置验证。测试失败必须传播到两个构建入口。

## 发布门槛与后续决策

发布要求完成密文双客户端真实联调、M4 延迟与资源报告、依赖许可记录、密码实现与集成安全审查、可恢复部署演练。备份文档明确频率与保留期，并以演练测量恢复点和恢复时间。

需要后续验证后冻结的项目限定为：MLS 库与密码套件、字节级协议 schema、编译器/标准库矩阵、密码验证参数、客户端密钥持久化与恢复格式。M0/M1 分别负责关闭这些决策，不影响当前的默认 E2EE、单进程、PostgreSQL、持久化后直推和会话事件日志架构。
