# LIM 加密与信任设计

## 会话模式与宿主授权

普通聊天默认使用 MLS。宿主可读（host）模式由管理员显式开启，创建者还须在建群时选择；模式持久化后禁止修改。客户端在加入和展示时标明模式。host 会话的服务端、宿主和能读取数据库或备份的主体可以读取正文。TLS、设备撤销、当前成员校验、加入可见区间、限流、日志脱敏和恢复代次同样适用。host 成员移除后立即拒绝访问，无需 MLS 换钥。需要群内容端到端保密的 Agent 作为独立 MLS 设备受邀入群。

嵌入时调用方是信任边界：宿主只为自己已认证的主体构造 Session，禁止从用户消息中接受任意身份。实例管理员控制哪一个宿主可打开数据库。进程内库与同一进程里的恶意插件之间没有隔离；不受信集成走已认证的网络接口。

下文的正文保密、身份根、KeyPackage、Welcome 与 epoch 保证适用于 MLS 会话。

## MLS 安全目标

LIM 默认使用端到端加密。正文与客户端生成的群资料由通信设备加密和解密；服务端、数据库与 TLS 代理只处理业务密文。TLS 1.3 保护连接认证与传输元数据，MLS 1.0 保护会话内容，两者同时启用。[TLS 1.3](https://www.rfc-editor.org/rfc/rfc8446.html)

采用标准 MLS 的群密钥机制与前向保密、入侵后恢复能力，应用侧明确身份绑定、设备管理和消息投递。密钥更新、状态删除与离线策略必须配套落实。[MLS 协议](https://www.rfc-editor.org/rfc/rfc9420.html)

| 对手或故障 | 系统承诺与处理 |
| --- | --- |
| 被动网络监听、篡改密文 | TLS 与 MLS 验证失败时拒绝处理 |
| 数据库或消息投递服务泄露 | 存储中仅有密文与公开密钥；正文私钥保留在客户端 |
| 服务端替换身份公钥 | 已固定的身份变更触发阻断；首次联系通过带外指纹核验建立更强信任 |
| 服务端扣留、重排或回放 | 客户端检查 MLS 状态、序号与去重记录；缺口补齐，持续失败展示同步错误 |
| 设备丢失或入侵 | 撤销会话与设备，冻结相关群写入，完成移除 Commit 后恢复发送 |
| 已授权收件人或端侧恶意软件 | 可读取该设备获得的明文；客户端提供本地保护与明确的身份提示 |

首次信任与端侧状态安全属于 E2EE 产品边界。UI 显示“身份已核验／首次信任／身份发生变化”，禁止将三者合并显示成同一种已验证状态。

## 协议与实现选择

单聊和群聊统一为 MLS group，每个设备对应一个 leaf。业务会话绑定独立的 `group_instance_id` 作为 MLS group ID，重建组时分配新实例 ID；业务账号和 MLS 设备身份分别建模。单聊含双方已授权设备，用户自己的其他设备也作为接收端。

服务端实现身份目录与 Delivery Service 职责；客户端执行 MLS 状态机。身份认证、密钥目录与投递各自具有独立契约，这符合 MLS 架构的职责划分。[MLS 架构](https://www.rfc-editor.org/rfc/rfc9750.html)

使用已有 MLS 实现，禁止自行实现 ratchet、HPKE、AEAD 或拼接加密算法。实施第 3 阶段对候选库完成许可证、维护状态、已公开安全审计、目标平台、状态序列化、标准向量与跨实现互操作评估，固定一个精确版本与密码套件。公开发布前要求选定库及 LIM 身份与恢复集成通过安全审查；本轮不引入尚未评估的密码库。

MLS 的认证数据必须绑定 LIM 协议版本、恢复代次、业务会话、组实例、设备、事件种类与客户端幂等键；Commit 还绑定预期 epoch 和成员变更意图。第 3 阶段冻结字节级编码、签名域隔离和参考向量。接收方同时验证 MLS group、认证发送设备与外层路由字段，拒绝跨会话重放和身份错配。

## 身份与设备登记

1. 首次登记时，客户端本地生成账号身份根密钥与设备密钥。账号身份公钥固定为联系人核验锚点，根私钥仅由用户授权的登记设备和离线恢复介质保管。
2. 每个设备持有独立签名私钥和 MLS 状态。设备证书包含账号、设备、公开签名密钥、授权版本和有效期，由账号身份根授权；服务端保存公开证书与撤销状态。
3. 添加设备需要账号登录和现有登记设备通过扫码等带外方式核验新设备公钥，再签发授权。密码登录成功只获得账号认证状态，设备获得 E2EE 群访问仍需相应授权与 Commit。
4. 客户端验证设备证书链和已固定的账号身份。联系人首次使用可选择 TOFU（首次信任），带外安全码核验后记录为已核验。身份根变更进入需人工重新核验的状态。
5. 根私钥丢失且无恢复介质时创建新身份，联系人看到身份重置；旧密文的可读性由旧客户端保存的密钥和历史决定。

设备授权证书格式和恢复介质格式在 第 3 阶段冻结，采用成熟密码库的签名与密钥管理接口，并纳入独立安全审查。首版恢复介质仅用于身份授权，聊天历史迁移另行设计。

## KeyPackage 与离线建群

客户端上传有有效期和数量上限的公开 KeyPackage，私钥保存在生成设备。目录原子发放一次性包，并进行账号、设备状态及申请频率检查；已发放包即使后续建群失败也不重新发放。客户端对有效期、套件、身份绑定与标准签名独立验证。

建群发起设备创建初始 MLS 状态，将初始公开组信息、成员授权与逐设备 Welcome 提交给服务端。服务器原子创建会话和分发记录；其他设备离线时可以稍后取得自己的 Welcome。客户端先持久化本地初始状态与重试记录，再提交；请求超时复用原始字节和幂等键。

KeyPackage 耗尽时返回可重试错误，等待设备补充；禁止使用任意占位公钥或跳过身份验证继续建群。

## 成员变更与 epoch

群角色分为 owner、admin、member。owner 转让后方可退出；admin 管理普通成员，只有 owner 管理管理员。普通成员可发消息、更新自己的密钥或退出；角色变更须走同一有序控制流程。服务端检查业务权限，客户端对实际 MLS 变更逐项检查相同权限。

退出或撤销先产生可验证的授权意图，再由仍留在群内的合法设备提交移除 Commit。设备所有者签名的撤销、管理员签名的移除和策略触发的失活各有独立验证规则，服务端与参考客户端共同执行；最后一个成员退出时关闭会话并撤销全部访问。

每次成员或设备变更由授权客户端生成 Commit。提交携带 `expected_epoch`、变更意图、Commit 和新设备 Welcome。服务端在单个会话事务中检查前置条件、写入控制事件、更新成员授权、发布 Welcome 并推进 epoch。客户端按序验证真实 Commit 与声明的 roster 变化一致后合并状态；校验失败进入隔离状态并停止发送。

并发 Commit 采用先提交者成功，其余返回 `epoch_conflict`。失败客户端丢弃本地待合并分支，拉取缺失事件，重新生成 Commit。客户端只能在持久化成功确认或同步确认原提交成功后合并自己的待提交状态。

移除成员和撤销设备需要严格控制“旧设备仍持有当前群密钥”的窗口：

- 收到撤销请求后，相关会话先标记为 `rekey_required`，立即拒绝新的应用消息和旧设备访问。既有密文按授权规则补齐，合法设备仍可提交必要的移除 Commit。
- 全部受影响设备从该群的新 epoch 移除后解除冻结；此后使用新 epoch 发送。
- 没有合法在线设备能完成 Commit 时，群保持待换钥状态并向客户端解释原因。
- SQLite 写事务和 PostgreSQL 元数据行锁将设备撤销及受影响会话冻结与发送事务串行化；撤销成功确认时，所有相关写入屏障已经生效。

已投递到被移除设备的数据由该设备持有。服务端停止新的访问，密码学上的后续内容隔离从移除 Commit 生效开始。

## 多设备 历史与状态持久化

新设备加入只获得加入后 epoch 的内容。账号历史不会因为密码登录自动解密。首版不自动迁移旧消息密钥；后续历史迁移由旧设备显式授权并通过独立加密通道完成。

客户端将“MLS 状态推进、已处理事件序号、解密结果或失败记录”原子写入本地持久化存储，再更新同步游标。发送端将“加密后 MLS 状态、原始密文、幂等键”原子保存后才上网发送；崩溃重试使用已保存密文，避免回滚后重复使用密钥状态。

客户端处理成功后按库契约删除旧消息密钥；离线补齐所需状态受明确保留窗口约束。首版建议设备连续离线 30 天触发失活与换钥流程；服务端加密控制事件保留期至少覆盖该窗口。超期或状态丢失的设备重新获准入群，通过新 Welcome 恢复未来消息；历史显示明确的不可恢复区间。

定期密钥更新纳入调度：活跃客户端在最长 24 小时内推动一次带新密钥材料的有效更新，并在设备风险事件后立即换钥。实际更新频率、离线窗口与状态清理需在安全评估和移动端能耗测试后冻结。

## 账号认证与会话

账号密码使用 libsodium 的 Argon2id 接口保存并按部署资源标定参数；密码验证并发受总内存上限约束。[libsodium 密码存储](https://doc.libsodium.org/password_hashing/default_phf)

访问令牌和刷新令牌使用密码学安全随机数，服务端只保存令牌摘要；刷新令牌轮换并检测重复使用。敏感凭据适用密码学处理，普通文件和构建产物无需额外摘要校验。[libsodium 随机数](https://doc.libsodium.org/generating_random_data)

WS 建连后通过首帧认证短期访问令牌与设备挑战签名，绑定账号、设备和连接；服务端挑战随机、一次性、有期限，并绑定当前连接。认证前只允许少量握手数据且设超时。令牌放在认证头或认证帧，避免 URL 泄露。续期、退出和撤销使已有连接及时重新校验或关闭；浏览器入口执行 Origin 白名单检查。敏感写入禁用 TLS 0-RTT。

## 元数据与运维

服务器可见账号、设备、群成员、事件种类、epoch、序号、时间、密文长度和来源网络信息。群名称、正文、引用、已读回执和未来附件密钥放在加密负载中。首版不提供服务端正文搜索、正文审核或明文推送摘要；滥用处理依靠速率、邀请、账号封禁及用户主动提供的证据。

日志禁止写入密码、访问令牌、私钥、消息正文、完整密文和 Welcome；业务 ID 默认脱敏，调试身份映射采用显式短期授权。指标标签只使用固定低基数字段。在线状态、输入中提示按需订阅并限频，首版仅提供自身连接状态。

数据库备份包含身份和关系元数据，需加密保存并限制访问。数据库回退通过显式恢复命令生成新恢复代次、撤销全部旧会话令牌并冻结全部恢复出的加密组。恢复流程重新核对当前设备和撤销清单，再由可信客户端协商建立新组实例和 Welcome；旧游标、旧组状态和未知结果的写请求停止自动重放。普通重启保持原恢复代次。备份点之后已丢失的密文由本地历史保留，补发需用户明确发起为新消息；具体恢复演练列入发布验收。
